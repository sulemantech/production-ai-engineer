# Week 1 — Arrays, Strings, Hashing, Two Pointers

**Objective:** The most common interview problem category. Build pattern recognition, not just solve-by-memory.

## Daily Drill
- **Day 1:** Array basics — 5 problems (e.g. two sum, best time to buy/sell stock, product except self).
- **Day 2:** Two pointers — 5 problems (e.g. container with most water, three sum, trapping rain water).
- **Day 3:** Sliding window — 5 problems (e.g. longest substring without repeat, max sliding window).
- **Day 4:** Hashing — 5 problems (e.g. group anagrams, subarray sum equals k).
- **Day 5:** String manipulation — 5 problems (e.g. valid parentheses, longest palindromic substring).
- **Day 6-7:** Mixed review set (10 problems, timed, from all of the above).

## Daily Interview Questions
1. When do you reach for two pointers vs. a hash map for the same-looking problem?
2. What's the time/space tradeoff sliding window makes vs. brute force?
3. Why does a hash map turn an O(n²) lookup problem into O(n)?
4. Walk me through how you'd explain your approach out loud before coding, for a two-pointer problem.
5. What's a common off-by-one mistake in sliding window problems, and how do you avoid it?

## Week 1 Assessment Gate
- Timed mock: 2 problems, 45 min total, explain approach out loud before coding.
- **Pass bar:** Solves both within time, states time/space complexity unprompted, explains reasoning before writing code (not silent typing).

## Milestone
25+ problems solved across arrays/strings/hashing/two-pointers, comfortable narrating approach before coding.
